# ТЗ для разработчика 2: экраны «Эффективность», «Механики»

Перед началом — обязательно прочитать `START.md` и `API-DATA.md` в этой же
папке. Здесь — только то, что специфично для ваших двух экранов.

Общие требования ко всем экранам (см. ТЗ, не повторять по-своему):

- Числа — ru-RU, пробел между тысячами, ₽ без копеек в KPI.
- Состояния: loading (скелетон), empty («Нет данных за период»), error
  (сообщение + повтор). Используйте общие компоненты из `shared/ui`,
  когда они появятся (см. `START.md`).
- Тема — только через переменные `var(--color-*)` из `app/styles/theme.css`.
- Адаптив — desktop-first, но обязательна мобильная вёрстка.

## Экран 1. «Эффективность» — маршрут `/efficiency` — `src/pages/efficiency/`

Данные: `dashboardStore.kpi`, `dashboardStore.mastersFiltered`,
`dashboardStore.marks`.

### KPI (4 шт.)

| Метрика      | Поле              | Ед. | Drill-down                                    | Tooltip                         |
| ------------ | ----------------- | --- | --------------------------------------------- | ------------------------------- |
| Т-фактор     | `T_FACTOR`        | %   | → график по мастерам ниже (на этом же экране) | «Загрузка мощностей»            |
| Потери на ЗН | `WASTED_TIME_MIN` | мин | → график потерь по мастерам (ниже)            | «Простой на ЗН, меньше — лучше» |
| Аккуратность | `ACCURACY`        | %   | → таблица по маркам (ниже)                    | «Качество исполнения»           |
| Выработка    | `LABOR_TIME`      | нч  | → «Механики» (второй ваш экран)               | «Суммарные нормо-часы»          |

### Графики (2 шт.) — горизонтальные столбчатые, данные из `mastersFiltered`

| График                   | X (значение)      | Y (категория) | Drill-down                                                                    | Drill-through         | Tooltip                              |
| ------------------------ | ----------------- | ------------- | ----------------------------------------------------------------------------- | --------------------- | ------------------------------------ |
| Т-фактор по мастерам     | `T_FACTOR`        | `MASTER_NAME` | клик по мастеру → экран «Мастера» (разработчика A) с выделением этого мастера | список ЗН мастера     | «Мастер: Т-фактор %. >0 переработка» |
| Потери на ЗН по мастерам | `WASTED_TIME_MIN` | `MASTER_NAME` | то же                                                                         | ЗН мастера с потерями | «Мастер: потери мин»                 |

Переход на экран «Мастера» с выделением — простой способ: навигация
`navigate('/masters', { state: { highlightMasterId: id } })`, страница
«Мастера» (у разработчика A) читает `location.state?.highlightMasterId`.
Договоритесь с разработчиком A о точном названии поля до реализации.

## Экран 2. «Механики» — маршрут `/mechanics` — `src/pages/mechanics/`

Данные: `dashboardStore.mechanicsFiltered` (уже отфильтровано
`MECHANIC_ID <> -1`).

⚠ **В ответе API нет `mechanicsPrev`** — если понадобится Δ к прошлому
месяцу для механиков, источника для неё сейчас нет (см. `API-DATA.md`,
открытые вопросы). В таблице ниже ТЗ просит «+Δ» для `T_FACTOR` — реализуйте
без Δ первой версией, пометьте `TODO`, сообщите лиду, чтобы он выяснил
источник данных.

### KPI (4 шт.) — агрегаты по механикам, считаются на фронте

| Метрика              | Как считать                                                                                                                                                         | Tooltip                        |
| -------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------ |
| Механиков            | `mechanicsFiltered.length` (либо `MECHANIC_COUNT` из `dashboardStore.kpi`, если нужно значение с учётом договорных — уточнить у лида, какое именно нужно по смыслу) | «Число механиков с ЗН»         |
| Суммарный оборот     | `SUM(TURNOVER)` по `mechanicsFiltered`                                                                                                                              | «Оборот по всем механикам»     |
| Среднее ЗН           | `AVG(ACCOUNT_COUNT)` по `mechanicsFiltered`                                                                                                                         | «Среднее число ЗН на механика» |
| Средняя аккуратность | `AVG(ACCURACY)` по `mechanicsFiltered`, игнорируя `null`                                                                                                            | «Средняя по механикам»         |

### Графики (2 шт.)

| График                 | Тип                    | Поля                                               | Drill-through | Tooltip                                                        |
| ---------------------- | ---------------------- | -------------------------------------------------- | ------------- | -------------------------------------------------------------- |
| Оборот по механикам    | гориз. столбчатый      | X=`TURNOVER`, Y=`MECHANIC_NAME`                    | ЗН механика   | «Механик: оборот ₽»                                            |
| Потери vs Аккуратность | **точечный (scatter)** | X=`WASTED_TIME_MIN`, Y=`ACCURACY`, точка = механик | ЗН механика   | «Механик: потери X мин, аккуратность Y%. Оптимум — левый верх» |

Scatter-график в Recharts — компонент `ScatterChart` +
`Scatter`/`ZAxis`/`Tooltip`. Учтите, что у части механиков `T_FACTOR`/
`ACCURACY` могут быть `null` (мало ЗН) — такие точки на scatter лучше
исключить из выборки (не рисовать точку с `null` координатой), но не
удалять запись из таблицы ниже.

### Таблица «Полная таблица механиков»

Колонки: `ACCOUNT_COUNT, TURNOVER, AVG_CASH, ARTICLE_WORK_RATIO,
AVG_SERVICE_TIME, LABOR_TIME, T_FACTOR` (+Δ — см. предупреждение выше),
`WASTED_TIME_MIN, ACCURACY`.

- Клик по строке → drill-through: `getAccountList(periodYm, dbIndex, { filterString: 'MECHANIC_ID=?', filterParam: [mechanicId] })`.
- Tooltip ячеек — как в таблице «Эффективность по маркам» на первом
  экране (аналогичные формулировки метрик).

## Порядок работы (рекомендация)

1. Начните с «Эффективность» — таблица и графики похожи на то, что уже
   частично встречается на «Обзоре», меньше новых паттернов.
2. «Механики» — оставьте на вторую очередь из-за scatter-графика и
   отсутствия `mechanicsPrev` (потребуется согласование с лидом по Δ).

Если что-то из таблиц кажется противоречивым исходному дизайну
(https://tochki-rosta.pplx.app/#/) — ориентируйтесь на данные из этого
документа (они сверены с реальным API), а по визуалу уточняйте у лида.
