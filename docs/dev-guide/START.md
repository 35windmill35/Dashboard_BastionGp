# Старт для разработчика

Проект: веб-дашборд «Точки роста» для BASTION GROUP. React 18 + MobX +
Recharts, архитектура FSD (Feature-Sliced Design), стили — CSS-модули.

Этот файл — точка входа. Если хочешь работать с помощью Claude в своей
сессии — приложи **весь этот файл + `API-DATA.md` + свой файл `TASK-DEV-*.md`**
как контекст в самом начале разговора.

## Как запустить проект

1. Установи Node.js LTS (nodejs.org), если ещё нет.
2. Склонируй репозиторий, открой папку в VS Code.
3. В терминале:
   ```
   npm install
   npm run dev -- --host
   ```
4. Открой адрес из вывода терминала (`Local: http://localhost:5173/`).
5. **Важно:** DB_GUID передаётся в адресной строке после хэша, иначе логин
   не сработает:
   ```
   http://localhost:5173/#/login?DB_GUID=3a166f27-77f9-4a0c-a732-84645966637d
   ```

## Что уже готово (не трогать / переиспользовать)

- `src/shared/api/` — HTTP-клиент, работа с сессией. Не дублировать, не
  писать свои fetch-запросы напрямую.
- `src/shared/config/` — константы, DB_GUID.
- `src/entities/user/model/authStore.js` — авторизация, текущий автоцентр
  (`authStore.currentFirm`), список баз, `authStore.dbIndex`.
- `src/entities/dashboard/model/periodsStore.js` и `dashboardStore.js` —
  вся работа с периодами и данными дашборда. Подробности — в `API-DATA.md`.
- `src/app/` — роутинг, защита маршрутов, тема.
- `src/app/styles/theme.css` — единый файл цветовых переменных. **Все
  цвета в CSS-модулях брать только отсюда** (`var(--color-surface)` и
  т.п.), хардкод хексов запрещён — иначе светлая тема (которую ещё
  предстоит доделать) не заведётся одним движением.

## Структура проекта (FSD)

```
src/
├── app/         — точка входа, роутинг, тема (общий слой, лид-разработчик)
├── pages/       — страницы-экраны, по папке на маршрут — ЗДЕСЬ ваша работа
├── widgets/     — крупные блоки интерфейса (шапка, KPI-блок и т.п.)
├── features/    — действия пользователя (смена периода, drill-through)
├── entities/    — сущности и MobX-сторы (user, dashboard) — уже готовы
└── shared/      — api, config, lib (утилиты), ui (базовые компоненты)
```

**Правило зависимостей FSD**: `pages` может использовать `widgets`,
`features`, `entities`, `shared`. `widgets` — `features`, `entities`,
`shared`. И так далее вниз. **Нельзя** тянуть импорт из `pages` в
`entities` или из одной `page` в другую `page` — если нужен общий кусок,
он должен переехать в `widgets`/`shared`.

Алиас `@` = `src/`, используйте его вместо `../../../`:
```js
import { dashboardStore } from '@/entities/dashboard/model/dashboardStore'
```

## Конвенции

- **Стили** — CSS-модули, файл `ИмяКомпонента.module.css` рядом с
  компонентом. `import styles from './X.module.css'`, классы через
  `styles.className`.
- **Компоненты**, читающие MobX-сторы, оборачивать в `observer` из
  `mobx-react-lite`:
  ```jsx
  import { observer } from 'mobx-react-lite'
  export const MyPage = observer(function MyPage() { ... })
  ```
- **Форматирование** — Prettier настроен, форматирование по сохранению
  файла должно работать автоматически (если нет — см. `.vscode/settings.json`
  и установи расширение Prettier).
- **Числа** — форматировать через `ru-RU`, пробел как разделитель тысяч, ₽
  без копеек в KPI (утилита форматирования будет добавлена в
  `shared/lib` — если её ещё нет на момент вашей работы, напишите
  временную и сообщите лиду, чтобы не расходились форматы).
- **`null` в данных** — показывать как «—», не приводить к 0 (см.
  `API-DATA.md`, там же про поля `-1` и лишние пробелы в именах).

## Компоненты общего назначения (`shared/ui`)

На момент написания этого гайда общие UI-компоненты (карточка KPI,
обёртки над Recharts, таблица, модалка drill-through, состояния
loading/empty/error) либо уже готовы в `src/shared/ui/`, либо появятся в
ближайшее время. **Прежде чем писать свою карточку/график с нуля —
проверьте, нет ли уже готового компонента в `shared/ui`.** Если экран
нужно делать раньше, чем компонент готов — верстайте временную версию
простыми `div`/CSS-модулем, но заложите такой же набор пропсов, какой
описан лидом, чтобы замена на общий компонент была быстрой заменой
импорта, а не переписыванием разметки.

## Важный подводный камень MobX + Recharts

Если добавляете в стор новое observable-поле, которое хранит массив/объект
и будет передаваться в графики (Recharts) — объявляйте его как
`observable.ref`, а не глубокий observable:

```js
makeAutoObservable(this, { myArrayField: observable.ref })
```

Иначе будет ошибка `[MobX] Dynamic observable objects cannot be frozen` —
Recharts/React пытаются сделать `Object.freeze` над данными, а глубокие
MobX-прокси этого не позволяют. Уже поправлено в `dashboardStore`,
`periodsStore`, `authStore` — если создаёте новый стор с похожими
данными, помните про это сразу.

## Что делать, если чего-то не хватает

Если для вашего экрана не хватает геттера в `dashboardStore` (например,
специфической сортировки или агрегата) — не лезьте в чужой файл стора
самостоятельно, если не уверены. Опишите, что нужно, лиду (в чате или
issue) — это общий файл, конфликт в нём сложнее решать, чем добавить
недостающее централизованно.
